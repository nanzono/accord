# 拒否は例外ではなく戻り値

- 状態: 採用
- 日付: 2026-09-15

## 文脈

書き込みの操作を呼ぶのが AI のとき、決まりに反する入力に例外を投げると、呼び手には「失敗した」としか伝わりません。何が足りなかったのかが分からないので、AI は同じ入力を言い換えて何度も試すことになります。

人が呼ぶ場合も事情は同じです。断られた理由が「例外が出た」までしか分からないと、正本のどこをどう直せばよいかを、書いた本人が探しに行くことになります。

## 決め

決まりに反する入力は、例外を投げず、「受け付けなかった理由」と「次に何をすればよいか」を持つ値として返します（`Rejection` と `NextAction`）。

戻り値には、欠けた欄の名前、その欄の書き方の例、実在する ID のうち近いものを入れます。返ってきたものをそのまま直して渡し直せば通る形にしてあります。

読むだけの操作と検査は、ファイルを一切変えません。書き込む操作は、決まりに通った入力だけを書き、通らない入力は書かずに次の一手を返します。

## 比べた選択肢

- **例外を投げ、呼び手に処理させる。** 「失敗した」しか伝わらず、同じ入力の言い換えを誘います。
- **通る形に直してから書き込む。** 人が決めていない値が正本に入ります。
- **理由だけ返し、次の一手は返さない。** 何を直せばよいかを呼び手が推測することになり、往復が増えます。

## 帰結

呼び手は、断りの戻り値だけを見て次の入力を組み立てられます。検査の結果も断りも同じ形（どこを、何に合わせるか）にそろうので、返ってきたものの読み方を 1 つ覚えれば済みます。

引き受けるものは、断りが戻り値である以上、呼び手が見なければ気づかれないことです。入口の層は、断りを成功と見分けられる形で返し続ける必要があります。
