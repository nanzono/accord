# 経歴の正本は accord の持ち物にし、AI のセッションは操作だけで読み書きする

- 状態: 採用
- 日付: 2026-10-13

## 文脈

accord が開く操作は 7 つで、材料の取り出しが返すのは看板のパッケージの裏づけの節だけでした。事実を書き足す操作も、節を読む操作もありません。文面を書くセッションは、経歴の正本のファイルを直接開いて読み、直接書くしかありませんでした。直接の書き込みは accord の制約を通らないので、書いた瞬間には何も断られず、食い違いは後の検査まで残ります。

正本の書き込みの大半は、既存の行の書き換えでした（増減が「1 行足して 1 行消す」形）。追記だけの操作では、この書き込みを accord の側に移せません。

## 決め

経歴の正本は accord の持ち物にし、文面を書くセッションは accord の操作だけで読み書きします。サーバーの説明にそう書き、どの返り値にも正本の置き場の絶対パスを入れません。道が accord しか無い形にするためです。

- **読み。** 材料の取り出しが、経歴の正本の節を公開不可の節（と下位の節）を除いてすべて返します。1 回で全部をそろえるため、返り値の長さの上限を MCP の宣言で 50 万字に上げます。確かめるための読みとして、節の一覧・節の読み・事実の検索を足します。
- **書き。** 事実の登記（節の末尾に 1 行足す）と、節の書き換え（節 1 つの本文を置き換える）を足します。書き換えは読んだときの指紋を受け取り、いまの指紋と違えば書きません。見出しの行と下位の節は変えず、ID の欄を消すことも変えることもさせません。書ける正本は、型の操作を持たない 3 つ（経歴・職務経歴書の台帳・見せ方）に限ります。書いた後の正本に、書く前に無かった違反が出るなら書きません。写しの鮮度だけは止めずに、読み比べる写しとして返します。
- **記録。** 設定で有効にしたとき、書き込みの操作は変えたファイルだけを git にコミットします。人の手の未コミットの変更があるファイルには書きません。
- **知らせ。** 起動時と読みの前に正本全体を検査し、違反があれば読みの返り値に件数と直し先を載せます。

## 比べた選択肢

- **追記だけの操作にする。** 書き込みの大半は既存の行の書き換えなので、追記だけではAI のセッションが正本を直接開く理由が残ります。
- **事実 1 件を型として持つ。** 型と関係とルールを増やすことになり、初版は節の単位で持つという決めから外れます。節の末尾の 1 行で足ります。
- **コミットをAI のセッションに任せる。** AI のセッションはデータの置き場のパスを知らない（教えない）ので、自分ではコミットできません。accord がしなければ、正本の変更の履歴が残りません。
- **書き換えで写しの鮮度も断る。** 元の節を正しく直すたびに写しは古くなります。それで止めると事実を直せなくなるので、断らずに読み比べる写しとして返し、直るまで読みの知らせに載せ続けます。

## 帰結

AI のセッションは、材料の取り出し 1 回で文面に要る節をそろえ、事実の追記と節の直しも accord を通して行えます。書いた瞬間に、新しく出た違反で断られ、読み比べる写しが返ります。

引き受けるものは 3 つです。

- 節の新設と見出しの変更は、この操作ではできません。人の手で直します。
- 材料の取り出しの返り値は大きくなります（経歴の正本の全文に近い量）。上限の宣言が効かないクライアントでは、返り値がファイルに逃がされます。
- 読むたびに正本の中身の指紋を取ります。変わっていなければ前回の検査の結果を使うので、検査を走らせ直すのは正本が変わったときだけです。
