# 写しの古さは、出典の節の本文の指紋で見つける

- 状態: 採用
- 日付: 2026-09-28

## 文脈

職務経歴書の台帳や媒体に貼る文面は、経歴の正本の節から中身を写して作ります。正本の節を後から直しても、写しの側は自分からは変わりません。直した後の正本に合わせて写しを読み直さない限り、古い記述が外に出続けます。

accord はこれまで、写しが指す出典の節が実在するかと、公開可の節かだけを見ていました。写した後に正本の節が変わったかは見ていなかったので、正本を直した後も検査は違反 0 を返し続けます。あわせて、台帳のうち読み方の絞りで外れた節は、読まなかったことも結果に出していませんでした。何を見たかが分からない「違反 0」は、見た範囲すべての合格と読まれます。

写しの文言が正本と合っているかを判定するのは、文の意味の判断です（[文面そのものを作らせない](0004-do-not-write-the-prose-itself.md)）。accord が機械で白黒を付けられるのは、「写した後に正本の節が変わったか」までです。

## 決め

写しの側に、写したときの出典の節の本文の指紋を控えます。欄の名前は「出典の指紋」で、「ID=指紋」の組を半角のスラッシュで区切って並べます（例「freelance-solo=1a2b3c4d / agency-employee=5e6f7a8b」）。書くのは台帳のブロックと、出典の節を宣言した提示物です。

指紋は、正本の節の本文（accord がその項目を読むのと同じ節で、下位の見出しの本文は含まない）から見出しの行を除き、各行の末尾の空白と前後の空行を落とし、改行を LF にそろえた文字列の SHA-256 の先頭 8 桁（16 進の小文字）です。作る関数は読み書きの層の 1 か所に置き、検査も、見本に書く指紋の算出も、この関数を使います。

整合の検査のたびに、控えた指紋と、いまの本文から作った指紋を比べます。違う出典があれば、その写しを名指ししたルール「写しの鮮度」の違反を 1 件挙げます。直し先には、変わった出典の節の ID と、読み比べた後に写しへ書く「出典の指紋」の行（いまの本文から作った値）を書きます。

出典の節に書いた ID に指紋の組が無い写しも、未確認の写しとして同じ違反に挙げます。出典の ID が実在しないか読めていないときは、実在の違反が別に挙がるので、その ID の鮮度は判定しません。

台帳の節のうち、読み方の深さにあって読み方の絞りで外れた節は、件数と見出しを 1 件の断りに書きます。出典の節を宣言していない提示物は、その件数を 1 件の断りに書きます。

## 比べた選択肢

- **写しに「写した日付」の欄を持たせ、正本の更新日と比べる。** いまの正本には節ごとの日付がありません。日付を足しても、人が直し忘れると効かず、直し忘れた写しは黙って通ります。本文の指紋なら、人が何かを書き忘れても、本文が変われば値が変わります。
- **写しの文言を正本の本文と突き合わせる。** 写しは要約や言い換えなので、文言の一致では判定できません。一致の度合いで判定すると、検査の結果に「たぶん」が混ざります。
- **控えの無い写しは見ない（控えを書いた写しだけを判定する）。** 控えを書き忘れた写しが、黙って検査の外に残ります。正本を直したのに古い写しが外に出続けたのと同じ形になるので、控えの無い写しは未確認として挙げます。
- **ファイル全体の指紋にする。** 同じファイルの別の節を直しただけで、そのファイルを出典にするすべての写しが挙がります。節ごとに取れば、挙がるのは直した節を出典にした写しだけです。

## 帰結

正本の節を直すと、その節を出典にした写しが次の検査で違反に挙がります。直し先の行をそのまま写しに書けば、違反は消えます。見る範囲は「写した後に正本の節が変わったか」で、写しの文言が正本と合っているかは、今までどおり見ません。

引き受けるものは 3 つです。

- 本文が 1 文字でも変われば挙がります。写しに関係しない追記でも挙がるので、読み比べて関係が無いと分かったときも、指紋の行を書き換える手間がかかります。
- 指紋は 8 桁なので、別の本文が同じ値になる重なりが理屈の上ではありえます。台帳 1 本と提示物十数本の規模では事実上起きない値として選んだので、写しの数が 2 桁以上増えたら見直します。
- 指紋を持たない既存の写しは、この決めを入れた直後の検査で、すべて未確認として挙がります。
