# 正本を Markdown のまま扱う

- 状態: 採用
- 日付: 2026-09-16

## 文脈

経歴の正本は、人が直接読み書きするものです。エディタで開いて直せること、git で差分が読めること、すでに使っている他の道具がそのまま動くことを壊したくありません。

いっぽう、人が書いた Markdown の書き方はそろっていません。見出しの深さ、項目を箇条書きで書くか表で書くか、項目名の言い換えが、書く人によっても、ファイルによっても違います。機械で読むには、この差をどこかで吸収する必要があります。

## 決め

正本は Markdown のまま置き、データベースや JSON には移しません。

書き方の違いは accord 側で吸収します。見出しの深さ、箇条書きか表か、項目名の言い換えは、設定ファイル `accord.toml` の `[reading]` の節で指定します。設定に書けば、正本のファイルを書き換えずに読めます。

Markdown の書式を知っている場所は、読み書きの層 1 つに閉じます。決まりを適用する層は、節と欄しか見ません。

## 比べた選択肢

- **保管先をデータベースや JSON に移す。** 機械は扱いやすくなりますが、正本を人の手から遠ざけた時点で、更新されない正本になります。
- **正本を accord の書き方に合わせて書き換えさせる。** その正本を読んでいる他の道具が壊れます。見出しを平らにすると、人が読むときに使っていた構造も消えます。
- **設定を置かず、どんな書き方でも読めるようにする。** 公開する道具に、特定の人の書き方に合わせた複雑さが入ります。

## 帰結

既存の正本と、それを読んでいる既存の道具を、そのまま使い続けられます。accord を使うのをやめても、正本は正本のまま残ります。

引き受けるものは 2 つあります。読み方の指定が設定に増えること、そして「何でも読める」わけではないことです。設定で指定できる範囲の外にある書き方は読めないので、指定できる範囲と書き方を文書で示す義務を負います。
