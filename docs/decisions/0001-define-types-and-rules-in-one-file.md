# 型とルールを 1 つのファイルに定める

- 状態: 採用
- 日付: 2026-09-16

## 文脈

accord が扱うデータの種類と、それらの間の決まりは、3 つの場面で別々に現れます。書き込みを断るとき、読んだものに警告を出すとき、全体を検査して一覧にするときです。同じ決まりを 3 か所に書き分けると、決まりを 1 つ足すたびに 3 か所を直すことになり、直し忘れた側が黙って古くなります。

もう 1 つ事情があります。この道具は公開して読んでもらうものなので、扱うデータの型と決まりを知りたい人に、Python のコードを読ませたくありません。

## 決め

型・関係・ルールは `src/accord/ontology.yaml` に 1 か所だけ定めます。Python の型のコードは、このファイルから `scripts/generate_models.py` で生成します。生成したコードもリポジトリに入れ、正本と一致しているかは生成器の検査モードで見ます。

資源 `accord://ontology` は、このファイルの中身をそのまま返します。AI はここを読んで前提をそろえます。

README の「データの型とルール」の節は人が書きますが、定義とずれていないこと（型の名前、関係の向きと名前、ルールの名前と現れ方、それぞれの数）はテストが見ます。

## 比べた選択肢

- **Python のコードを正本にして、YAML を書き出す。** 生成の仕組みは要らなくなりますが、型と決まりを知りたい人にコードを読ませることになります。
- **生成せず、3 か所にそれぞれ書く。** 決まりを 1 つ足すたびに 3 か所を直すことになり、直し忘れが黙って進みます。
- **README の節も定義ファイルから生成する。** かみ砕いた説明を定義ファイルに持ち込むことになり、公開する定義が README の都合で太ります。
- **README と定義の一致を、そのつど目で確かめる。** 定義を直したときに追随せず、README だけが古くなります。

## 帰結

決まりを 1 つ足すときに直すのは 1 ファイルで、コードは生成し直します。定義ファイルは公開物としてそのまま読まれるので、どの型が何を指すかを日本語で読める状態に保てます。

引き受けるものもあります。生成の仕組みを保守し続けること、生成したコードが正本と一致していることを検査で見続けること、定義ファイルの欄の説明を人が読める文で書き続けることです。
