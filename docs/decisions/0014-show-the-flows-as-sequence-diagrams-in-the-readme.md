# 説明書に、操作の流れをシーケンス図で載せる

- 状態: 採用
- 日付: 2026-10-14

## 文脈

操作が 18 に増え、AI が文面を書くときと、経歴の事実を書き足し・直し・並べ替えるときで、どの操作をどの順に呼ぶかが表だけでは読み取りにくくなりました。表は 1 行に 1 つの操作を書くので、「先に節を読み、その指紋を渡して書き換える」「書いた後に、古くなった写しを読み比べる」のような順番を持つ流れが見えません。

## 決め

説明書の「動くとこうなる」の節に、Mermaid のシーケンス図を 2 枚載せます。1 枚は文面を書くとき、もう 1 枚は利用者が AI に経歴の書き足しと直しを頼むときです。登場するのは、利用者・AI（Claude Code など）・accord・経歴のファイル・git の 5 つで、架空でない名前は使いません。経歴のファイルを直接開く道は、利用者にも AI にも描きません。

## 比べた選択肢

- **構造の説明（ARCHITECTURE.md）に置く。** 構造の説明は層と責務を書く場所で、利用者が操作を呼ぶ順番は説明書の読み手が知りたいことです。
- **画像にして置く。** Mermaid の図は GitHub の画面でそのまま図になり、文字として差分を追えます。画像は直すたびに描き直しが要ります。
- **人がファイルを直接直す流れも描く。** 経歴のファイルは、人も AI も直接開いて直さず、accord の操作だけで変えます（[0015](0015-close-every-direct-edit-path-with-accord-operations.md)）。図に直接触る道を描くと、読み手がその道を使ってよいと受け取るので、描きません。

## 帰結

説明書の読み手は、表で操作の名前を、図で呼ぶ順番を読めます。

引き受けるものは 1 つです。

- Mermaid を図にしない画面では、図の元の文がそのまま見えます。操作の名前は文のまま読めるので、意味は失われません。
