# MCP サーバーにする

- 状態: 採用
- 日付: 2026-09-15

## 文脈

正本を守りたい瞬間は、文章を書いているその最中です。決まりを手引きや覚え書きに書いておいても、書く瞬間には思い出せません。

AI と一緒に職務経歴書やプロフィールを書くとき、必要な材料は正本の中にあり、書いたものが正本と食い違っているかどうかも、その場でしか分かりません。書き終えてから確かめる形にすると、直しが書き直しになります。

つまり必要なのは、決まりを書いた文書ではなく、書いている最中に呼べる相手です。呼べる相手にするには、AI の側から呼び出せる口が要ります。

## 決め

accord は MCP（生成 AI から外部の道具を呼び出すための共通の口）のサーバーとして動きます。AI は文章を書く途中で材料を取りに来られ、書いたものをその場で検査できます。決まりを「読んで覚えておくもの」ではなく「呼べば返ってくるもの」にするための口として、MCP を選びました。

同じ処理を Python から直接呼ぶ道も残します。手元のファイルを検査するだけなら、MCP を通す必要がないからです。

## 比べた選択肢

- **AI に渡す指示文へ決まりを書き足す。** 読ませたかどうかを確かめられません。指示文が長くなるほど効きが落ちます。
- **コマンドとして走らせ、書き終えてから検査する。** 書いている最中に材料を渡せず、食い違いに気づくのが書き終えた後になります。
- **文章を書く画面の拡張として作る。** 書く道具を 1 つに決めさせることになります。

## 帰結

AI から使うときは、設定ファイルに 1 か所書けば口がつながり、どの決まりが効くかを利用者が覚えなくて済みます。ネットワークには出ず、手元のファイルだけを見ます。

引き受けるものは、入口が 2 つになることです。MCP のツールとして公開する層と、Python から直接呼ぶ道の両方を保ちます。そのため MCP の層は引数の確認と戻り値の整形だけに保ち、判断はその下の層に置いています。診断に使う足跡も、直接呼びで消えないように下の層で組み立てます。
