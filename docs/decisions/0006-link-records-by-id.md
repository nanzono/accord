# 見出しではなく ID で結ぶ

- 状態: 採用
- 日付: 2026-09-18

## 文脈

正本の項目（職歴の枠・受託案件・公開記録・機能・パッケージ。型の意味は README の「データの型とルール」）どうしを見出しの文字で結ぶ書き方には、穴が 2 つあります。

1 つは、見出しを書き換えると参照が切れることです。文面の都合で見出しを直した瞬間、それを指していた側が、実在しないものを指すことになります。

もう 1 つは、見出しの中に「・」や記号が入ると、複数を並べる欄（たとえば機能の裏づけの欄）で、どこまでが 1 つの値なのかを機械が断定できないことです。区切りを断定できない以上、指した先が実在するかどうかも判定できません。

## 決め

職歴の枠・受託案件・公開記録・機能・パッケージの 5 つに、人が振る短い ID の行を持たせます。ほかの項目からこれらを指すときは、見出しや名前ではなく、この ID を書きます。

ID は人が付けます。機械が見るのは 3 つだけで、形（英小文字・数字・ハイフンで 3〜40 字、先頭と末尾は英数字）、5 つの種類をまたいで重なっていないこと、指した先が実在することです。

1 つの欄に複数の ID を書くときの区切りは、半角の「/」に固定します。設定では変えられません。

## 比べた選択肢

- **見出しの文字で結んだまま、検査を厚くする。** 見出しを書き換えたときに参照が切れることは、検査では防げません。
- **ID を機械に作らせる。** 意味の無い文字列が、人の読む正本に混ざります。
- **区切りの記号を設定で選べるようにする。** 見出しの中に入りうる記号と、いつまでも衝突します。
- **保管先を JSON や YAML に移す。** 結び方が見出しの文字のままなら穴は消えず、正本を人の手から遠ざける代償だけが残ります。

## 帰結

指した先が実在するか、形が合っているか、重なっていないかを、機械が断定できます。見出しの表現は、参照を気にせずいつでも直せます。

引き受けるものは、正本に ID の行が 1 行増えること、新しい項目を書くたびに人が ID を考えることです。区切りを固定したので、区切りの書き方を型の定義ファイル（`src/accord/ontology.yaml`）の欄の説明と README で示します。
