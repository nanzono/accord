# 要件の番号を持たないテストには、docstring の 1 行目に理由を書く

- 状態: 採用
- 日付: 2026-09-25

## 文脈

要件とテストは、テストの関数名に入れた `REQ-014` の形の番号で結んでいます（[要件とテストを番号で結び、機械で突き合わせる](0007-link-requirements-and-tests-by-number.md)）。突合検査が見るのは、番号を名前に持つテストだけです。

ところが `tests/` には、番号を名前に持たないテストがあります。テストの中の突き合わせの道具が壊れていないかを試す自己試験や、テストの表が型の正本と食い違っていないかを見張るテストのように、要件に結ばない理由のあるものです。当たる要件があるものは、名前に番号を付けて要件に結びます。

その理由は、このリポジトリのどこにも書かれていませんでした。番号の無いテストは突合検査で落ちないので、理由の無いまま増えても気づけません。テストを読んだ人は、そのテストが要件を確かめ忘れたものなのか、わざと番号を付けていないものなのかを、名前からは区別できません。

## 決め

要件の番号を名前に持たないテスト関数（`tests/` の `test_*.py` にある、名前が `test_` で始まり `test_REQ_` で始まらない関数）は、docstring の 1 行目を `番号なし: ` で始め、その後ろに理由の文を書きます。

```python
def test_the_rejection_paths_cover_every_write_constraint(settings):
    """番号なし: 拒否の経路の表が、型の正本の制約をすべて覆っているかを試す。accord の振る舞いではなく、テストの表と型の正本の食い違いを見張るものなので、要件に結ばない。

    （ここから下は、ほかのテストと同じ説明）
    """
```

理由の文に書くのは 2 つだけです。何を試すテストかと、なぜ要件に結ばないかです。

これを `tools/check_req_coverage.py` の項目「番号なしのテストに理由がある」が見ます。docstring が無い、1 行目が `番号なし: ` で始まらない、その後ろが空、のどれかで落ち、テストの場所と関数名を 1 件 1 行で出します。合格のときは、番号を持たないテストの本数を出します。この項目は、ほかの突合の項目と同じく CI でテストより先に走ります。

## 比べた選択肢

- **番号を持たないテストを禁じる。** 自己試験や網羅の見張りのように、accord の外から見える振る舞いではないものを確かめるテストまで、要件を作らないと書けなくなります。要件は外から見える振る舞いを述べるものなので、そこに道具の話が混ざります。
- **理由をテストの外の一覧に書く。** テストを足す人と一覧を直す人が別になり、一覧が古くなっても気づけません。docstring なら、テストと同じ場所で読め、テストを消せば理由も一緒に消えます。
- **pytest の印（marker）で番号なしを宣言する。** 印は理由の文を持てず、テストを収集しないと数えられません。docstring の 1 行目なら、テストを走らせずに構文木を読むだけで数えられます。
- **本数だけを数えて、上限を置く。** 上限の値に根拠が無く、上限の内側なら理由の無いテストが通ります。

## 帰結

番号を持たないテストは、名前を見て docstring の 1 行目を読めば、わざと番号を付けていないことと、その理由が分かります。理由の無い番号なしのテストは、CI で落ちます。本数は突合検査の出力に毎回出るので、増えたことに気づけます。

引き受けるものは 2 つです。

- 番号を持たないテストを足すたびに、理由の文を 1 行書く手間がかかります。
- 検査が見るのは、理由の文があることだけです。理由が正しいか、本当は要件を確かめるべきテストではないかは、差分を読む人が確かめます。
