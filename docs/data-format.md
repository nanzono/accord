# 正本の書き方（accord の形）と、accord で行える変更

accord が読み書きする経歴データの書き方は 1 通りに決まっています。これを accord の形と呼びます。accord は読み方を変える設定も引数も受け付けません。書き方の違う正本を持っている人は、accord の形に変換してから使います。前の版の設定ファイル（`accord.toml`）を持ち、語彙のファイルを持たない置き場は、移行の操作（`migrate_data`）で accord の形の置き場にします。移行は、設定ファイルに書いた置き場と読み方がこの文書の形と同じことを確かめてから、設定ファイルの語彙から `vocabulary.md` を作り、設定ファイルを消し、その 2 つを 1 件のコミットにします。同梱の見本 `samples/data/`（経歴データの置き場）と `samples/presentations/`（提示物の置き場）が、accord の形の実例です。見本は架空の人物と架空の案件だけでできていて、整合の検査の違反は 0 件です。

経歴の正本のファイルは、人も AI も直接開いて直さず、accord の操作だけで変えます。後半の表は、ファイルの中に現れる書き方（データの形）のどれについても、起こりうる変更を accord の操作で行えるか、決めた理由で断るかを、「データの形 × 変更の種類」で示します。表の 1 行の「変更の種類」の 1 つずつを 1 マスと呼び、マスごとに `tests/test_completeness.py` のテストが 1 本以上あります（テストの名前は `test_REQ_540_<形>_<変更>`）。同梱の見本に無い形は、架空の語で見本（`samples/data/career_master.md` の「書き方の見本」の節）に足してあります。

## 置き場とファイル

accord は起動の引数で 2 つの置き場を受けます。

- `--data`: 経歴データの置き場。git の作業ツリーの根であることを求めます。中に置くのは、下の 7 つの正本のファイルと語彙のファイル `vocabulary.md` と、それらを入れるディレクトリだけです。accord を通さない未コミットの変更か、accord を通さないコミットがあると、accord は書き込みを断ります。片づけるのは、未コミットの変更を捨てる操作（`discard_uncommitted`）と、コミットを取り消す操作（`revert_commit`）です。
- `--presentations`: 提示物と媒体ごとの規約の置き場。省くと、提示物を 0 件として読みます。

経歴データの置き場の中の正本のファイルは、名前と置き場が決まっています。

| ファイル | 何の正本か |
|---|---|
| `career_master.md` | 経歴の正本。職歴の枠と受託案件を 1 つのファイルに入れ子で持つ |
| `keirekisho/daicho.md` | 職務経歴書の台帳 |
| `misekata_master.md` | 見せ方の正本（禁じた言い回し）。accord は中身を型として持たない |
| `product/features.md` | 機能の台帳 |
| `product/packages.md` | パッケージ定義 |
| `product/positioning.md` | 売り方の決め |
| `public_records.md` | 公開記録 |

## 語彙

語彙は `vocabulary.md` に、種類ごとの節（深さ 2 の見出しに種類の名前）を置き、語を `- 語` の形で 1 行ずつ書きます。1 行目の見出しは `# 語彙` です。種類は 6 つで、語が 0 件の種類も節を置きます。語は、語彙に語を足す操作（`add_term`。種類の節の末尾に 1 行足す）と語彙から語を消す操作（`remove_term`）で変えます。正本の節が使っている語（下の各ファイルの読み方のうち、語彙と照らす欄の値）は消せないので、語を直すときは、新しい語を足し、使っている節を `revise_section` で直してから、古い語を消します。

- 媒体: 決めの適用範囲と、提示物の宛先に使う。提示物は、提示物の置き場の下の、媒体と同じ名前のディレクトリから読む
- 決めの適用先: 媒体ではない決めの適用範囲の語
- 機能の分類: 機能の台帳の節の見出し
- パッケージの仮説の状態
- 公開記録の種類
- 公開記録の役割

## 各ファイルの読み方

- **欄**は、箇条書きの「- ラベル: 値」で書きます（区切りは半角か全角のコロン）。ラベルの末尾の括弧書き（但し書き）は落としてから読みます。下の「欄のラベルの読み替え」に挙げたラベルは、決まった欄に読み替えます。1 つのラベルを複数の欄に読み替えると、同じ値がその欄すべてに入ります。
- **売り方の決め・公開記録**: 深さ 2 の見出しの節が 1 件ぶんです。
- **パッケージ定義**: 深さ 2 の見出しの節が 1 件ぶんです。パッケージの型の欄（ID・パッケージ名・想定買い手・仮説の状態・束ねる機能・最終更新・判定根拠・出典・崩れる条件）を 1 つも持たない節は、覚え書きの節として読み飛ばします。
- **機能の台帳**: 深さ 2 の見出しが機能の分類で、その下の表の 1 行が機能 1 件です。
- **経歴の正本**: 束ねる見出し「職歴・案件（新しい順）」の下の、深さ 3 の見出しの節が職歴の枠、深さ 4 と 5 の見出しの節が受託案件です。欄を 1 つも持たない深さ 4 と 5 の見出し（案件を束ねるためだけの見出し）は読み飛ばします。束ねる見出しの外の節（基本情報など）は、型としては読まず、節としてだけ読み書きします。
- **職務経歴書の台帳**: 見出しが「案件」で始まる深さ 2 の節が案件 1 件、「枠」で始まる節が在籍職歴の枠 1 件です。番号は見出しの前置きに続く数字から読みます。欄は 2 列の表（1 列目が欄の名前、2 列目が中身）と箇条書きで書き、行頭のラベル「畳み行」は箇条書きの記号なしでも欄として読みます。
- **見せ方の正本**: 見出しが「本人が禁じた言い回し」の節（深さは問わず、末尾の括弧書きは見ない）の、最初の表の 1 列目を禁じた言い回しとして読みます。
- **媒体ごとの規約**: 提示物の置き場の `{媒体}/channel.md`（ファイルの中の `{channel}` を媒体の名前に置き換えた場所）の箇条書きです。ファイルが無い媒体の規約は空です。
- **提示物**: 提示物の置き場の、媒体と同じ名前のディレクトリの下の Markdown のうち、宣言する束の行を持つものです。

## 形を決める名前

accord のコードが名前で使う語は、次の一覧ですべてです（`src/accord/vocabulary/settings.py` の「accord の形を決める名前」の定数と同じで、`tests/test_reading_settings.py` が突き合わせます）。

- ファイルの名前と置き場: `product/positioning.md`、`product/packages.md`、`product/features.md`、`career_master.md`、`keirekisho/daicho.md`、`.`、`public_records.md`、`misekata_master.md`
- 語彙のファイルと見出し: `vocabulary.md`、`語彙`
- 語彙の種類の名前: `媒体`、`決めの適用先`、`機能の分類`、`パッケージの仮説の状態`、`公開記録の種類`、`公開記録の役割`
- 職歴の節を束ねる上位の見出し: `職歴・案件（新しい順）`
- 台帳の見出しの前置き: `案件`、`枠`
- 台帳の行頭に書く欄のラベル: `畳み行`
- 欄のラベルの読み替え: `期間 / 所属・立場`（`期間`・`所属`・`立場` に読む）、`業種・規模`（`業種`・`規模` に読む）、`技術スタック`（`技術` に読む）、`課題・背景`（`課題` に読む）
- パッケージとして読む節を見分ける欄のラベル（型の正本のパッケージの欄と同じ）: `ID`、`パッケージ名`、`想定買い手`、`仮説の状態`、`束ねる機能`、`最終更新`、`判定根拠`、`出典`、`崩れる条件`
- 媒体ごとの規約のファイル: `{channel}/channel.md`
- 禁じた言い回しの節の見出し: `本人が禁じた言い回し`

これ以外の見出し・値は利用者のデータの中身で、accord の公開側（コード・見本・説明書・この文書）には書きません。

## 表

| データの形 | 変更の種類 | accord の操作か、断る理由 |
|---|---|---|
| 最上位の見出し（深さ 1） | 足す・消す・並べ替える・名を変える | 足すは `add_section`（親を省いてファイルを渡す）、消すは `remove_section`、並べ替えるは `move_section`（新しい親を省き、前に置く深さ 1 の節を渡す）、名を変えるは `rename_heading` |
| 下位の見出し（深さ 2〜6） | 足す・消す・動かす（親を変える）・名を変える・深さを変える | 足すは `add_section`、消すは `remove_section`、動かすと深さを変えるは `move_section`（深さは新しい親の 1 段下にそろう）、名を変えるは `rename_heading` |
| 同じ名前の見出しが、同じファイルの別の親の下にある | 道筋で 1 つに指す・直す | 見出しの道筋（上の見出しから「 > 」でつないだもの）で 1 つに決まる。同じ親の下に同じ名前が並ぶときだけ断る |
| 箇条書きの項目（字下げ 0） | 足す・消す・並べ替える・本文を直す | `revise_section`（節の本文を置き換える）。事実を 1 行足すだけなら `record_fact` |
| 入れ子の箇条書き（字下げ 2〜4） | 入れ子ごと足す・消す・入れ子の深さを変える | `revise_section` |
| 箇条書きの続きの行（1 つの項目を複数行で書く） | 複数行のまま直す | `revise_section`（行で切らず、節の本文ごと置き換える） |
| 公開可否の行 | 足す・消す・並べ替える・値を変える | `revise_section` に、書いた後の公開可否の行の値の並びを申告させる。1 行の値だけなら `set_disclosure`（2 行以上の節では何行目かを渡す）。公開可否の行を 2 行以上持つ節に、公開可否の行の無い項目は足せない |
| 公開可否の行の別の書き方（区切りが「＝」、番号つきの箇条書きの中、記号の無い続きの行、太字のラベル） | 値を変える・足す・消す | 公開可否の行として読むので、上の行と同じ。値を変えても、書き方（区切り・記号・太字）はそのまま残る |
| 番号つきの箇条書き | 足す・消す・並べ替える | `revise_section` |
| 表の行 | 行を足す・消す・並べ替える・欄の値を直す・列を足す | `revise_section`。機能の台帳の行も同じで、ID の形や指す先は書いた後の整合の検査が見る |
| 「名: 値」の欄の行 | 値を直す・欄を足す・消す | `revise_section`。ID の欄は変えられない（下の行）。必須の欄を消すと、読めないブロックができるので断る |
| 太字の欄（`**名**：値`） | 値を直す | `revise_section` |
| 段落の文の行（字下げ 0 の、箇条書きでも欄でもない行） | 足す・消す・直す | `revise_section` |
| 太字で始まる文の行（`**…**` で始まるが「名：値」の形でない行） | 足す・消す・直す | `revise_section` |
| 引用（行頭の `>`） | 足す・消す・直す | `revise_section` |
| 水平線（`---`） | 節の境と取り違えない・足す・消す | 見出しは `#` で始まる行だけなので、水平線は本文の一部として `revise_section` で扱う |
| コードの囲み | 囲みの中を直す・囲みを足す・消す | `revise_section`。囲みの中に「#」で始まる行は書かない（見出しとして読まれるので、本文の見出しの行として断る） |
| ID を持つ行 | ID を変える・ID を持つ節を消す・動かす | ID は変えられない（断る）。ID を持つ節を消す・動かすのは `remove_section`・`move_section` で、ほかの項目がその ID を指していれば書いた後の整合の検査の違反で断る |
| 見出しの階層の飛び（深さが 2 段以上深くなる見出し） | 飛びを作る | accord の操作では起こらない。節を足す・動かす操作は、新しい節をいつも親の 1 段下に置く |

## 書かないこと

- コードの囲みの中に、「#」で始まる行を書かない。accord は見出しを行の頭の `#` で見分けるので、囲みの中でも見出しとして読みます。
