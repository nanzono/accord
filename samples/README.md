# 同梱のサンプルについて

`source/` の中身は、すべて架空の人物と架空の案件である。実在の人物・会社・媒体とは関係が無い。
accord のテストと、初めて動かすときの確かめは、このサンプルの上で走る。

## 書き方の違う第 2 のサンプル

`source_alt/` は、`source/` と同じ人・同じ案件・同じ中身を、違う書き方で書いた正本である。
指す設定は `accord_alt.toml` で、こちらには読み方を書く `[reading]` の節がある。

自分の正本が accord の読み方に合わないとき、正本のほうを書き換えないと使えないのでは、
すでにその正本を読んでいる他の道具が壊れる。第 2 のサンプルは、正本を書き換えずに、
設定で読み方のほうを合わせられることを、実際に動く形で示すために置いてある。
この正本でも、8 種が断り 0 件で読め、制約の検査が `source/` とまったく同じ結果を返す
（`tests/test_compat.py` が 1 対 1 で見ている）。

| 何が違うか | `source/` の書き方 | `source_alt/` の書き方 |
|---|---|---|
| 職歴の枠と受託案件の置き場 | 別々のファイル | 1 つのファイル（`career_master.md`）に入れ子で同居し、深さ 3 と 4・5 で分かれる |
| ブロックの見出しの深さ | どの正本も深さ 2 | 正本ごとに違い、上位の節でも絞る |
| 正本でない節 | 置いていない | パッケージ定義・台帳・職歴に混ざっている（読まない見出しと前置きで分ける） |
| 台帳の欄 | 箇条書き | 2 列の表と、箇条書きの記号が無い行頭の宣言 |
| 台帳の案件番号 | 欄に書く | 見出しの「案件」に続く数字から読む |
| 欄のラベル | 型の欄の名前そのまま | 1 つのラベルが 3 欄を兼ねたり、末尾に但し書きの括弧が付く |
| 提示物の置き場 | `presentations/<媒体>/` | 媒体ごとのディレクトリの直下（提示物でないファイルも同居する） |
| 媒体の規約 | 見せ方の正本 1 つの中の、媒体の名前の節 | 媒体ごとの `channel.md` |
| 禁じた言い回し | 深さ 2 の節の箇条書き | 深さ 3 の節（見出しに但し書きの括弧）の、最初の表の 1 列目 |
| 公開記録 | `public_records.md` の深さ 2 の節 | `public_works.md` の深さ 3 の節。欄のラベルも 1 つ違う（「発行元か主催」ではなく「発行元」） |

## 読み方を設定で差し替える

設定ファイルの最上位に書ける節は `[source]`、`[vocabulary]`、`[reading]` の 3 つだけで、それ以外の名前を最上位に書くと、書いた名前と書ける名前の一覧を添えて起動時に止まる（サーバーは立ち上がらない）。

設定ファイルの `[reading]` の節が、正本の書き方を持つ。**この節を書かなければ、すべてが既定値になり、
`source/` と同じ書き方で読む**（`accord.toml` はこの節を持たない）。書ける鍵は次のとおりで、
綴りを間違えた鍵は、設定を読んだ瞬間に鍵の名前と書ける名前の一覧つきで止まる。

**正本ごとの節を選ぶ鍵。** `[reading.positioning]`、`[reading.packages]`、`[reading.capabilities]`、
`[reading.career]`、`[reading.engagements]`、`[reading.resume_ledger]`、`[reading.public_records]`、
`[reading.presentations]`、`[reading.presentation_rules]` に、同じ鍵を書ける。

| 鍵 | 何を決めるか | 既定値 |
|---|---|---|
| `heading_levels` | その正本のブロックとして読む見出しの深さの一覧 | `[2]` |
| `under_headings` | 上位のどの節の下だけを読むか。空なら絞らない | 空 |
| `heading_prefix` | 見出しがこの文字列で始まるものだけを読む | 空 |
| `skip_headings` | この見出しの節（とその下の節）は読まない | 空 |
| `skip_sections_without_fields` | 欄を 1 つも持たない節を、束ねるための見出しとして読み飛ばすか | `false` |
| `fields_from_table` | 2 列の表の行も、ラベルと値の欄として読むか。箇条書きの欄に足して読む | `false` |
| `bare_labels` | 箇条書きの記号が無い行頭の宣言（`畳み行: 値`）も欄として読むラベルの一覧 | 空 |
| `entry_number_from_heading` | 台帳の案件番号を、見出しの前置きに続く数字から読むか | `false` |

職歴の枠と受託案件のように、1 つのファイルを 2 種の正本として読むときは、`[source.files]` の
2 つの鍵に同じファイル名を書き、深さで分ける。新しい鍵は要らない。

**公開記録を使うときだけ書く鍵。** 公開記録（登壇・記事・リポジトリなど）を持つなら、設定に 3 つ足す——
`[source.files]` の `public_records`（置き場）と、`[vocabulary]` の `public_record_kinds`（種類の語）と
`public_record_roles`（役割の語）である。置き場を書かなければ公開記録を 0 件として読み、提示物の本文の
URL を正本と突き合わせる検査も行わない（行っていないことは、検査の断りに 1 行出る）。置き場を書いて
語彙の 2 つを書き忘れると、鍵の名前を添えて起動時に止まる。

**欄のラベルの読み替えの鍵。** 正本を問わず共通なので、`[reading]` の直下に 1 度だけ書く。

| 鍵 | 何を決めるか | 既定値 |
|---|---|---|
| `strip_label_note` | 欄のラベルの末尾の括弧書きを落としてから読むか | `false` |
| `[reading.labels]` | 正本のラベルと、型の欄のラベルの読み替え。1 つのラベルを複数の欄に読み替えると、同じ値がその欄すべてに入る | 空 |

**提示物の鍵（`[reading.presentations]`）。**

| 鍵 | 何を決めるか | 既定値 |
|---|---|---|
| `directories` | 提示物を探すディレクトリの一覧。空なら、設定が提示物として指したディレクトリの下を全部たどる | 空 |
| `require_declaration` | 宣言の行（`- 宣言する束`）を持つ Markdown だけを提示物として読むか | `false` |

**見せ方の正本の鍵（`[reading.presentation_rules]`）。**

| 鍵 | 何を決めるか | 既定値 |
|---|---|---|
| `channel_rules_from` | 媒体の規約を、1 つのファイルの媒体名の節から読むか（`"one_file"`）、媒体ごとのファイルから読むか（`"per_channel_file"`） | `"one_file"` |
| `channel_rules_file` | 媒体ごとのファイルのときの置き場。媒体の名前が入る場所を `{channel}` で書く | 空 |
| `forbidden_phrases_heading` | 禁じた言い回しの節の見出しの名前 | `"禁じた言い回し"` |
| `forbidden_phrases_any_level` | 見出しの深さを問わずに探すか | `false` |
| `forbidden_phrases_from` | 節の中身を、箇条書きから読むか（`"bullets"`）、節の最初の表の 1 列目から読むか（`"table"`） | `"bullets"` |

見出しの名前を照らし合わせるときは、末尾の括弧書きを落としてから比べる。中身は、節の最初の表か、
最初の箇条書きの塊だけを読む。同じ節に別の話の表や箇条書きが続けて置かれている正本があり、
全部を拾うと禁じた言い回しでないものが混ざるからである。

書きの操作（決めの登記・機能の登記・パッケージの改訂・公開記録の登記）は、読み方をどう設定しても
`source/` と同じ書き方で書き足す。広げた読み方はその書き方も読めるので、書いたものをそのまま読み直せる。
裏づけの節は `career.md` か `engagements.md` の見出し、または `public_records.md` の公開記録の名前を
そのまま書き、複数あるときは半角の `/` で区切る。
「・」などほかの記号でつなぐと、つないだ全体が 1 つの見出しとして読まれ、実在しないと判定される。

## 検査が読む欄の書き方

整合の検査（`check_consistency`）は、正本の次の欄を読む。欄の名前も区切りも、下の形で書く。

| 欄 | どのファイルのどこ | 書き方 |
|---|---|---|
| 最終更新 | `packages.md` の各節 | `- 最終更新: 2026-09-12`。この日が、その束を前面に出した決めの日付より古いと鮮度の違反になる |
| 例外 | `positioning.md` の各ブロック | `- 例外: なし`、または `- 例外: presentations/<媒体>/<ファイル名> — 理由`。1 行 1 件で、行を足せば何件でも書ける。ここに書いた提示物は、宣言と看板の一致の検査を飛ばす |
| 宣言する束 | 提示物の先頭 | `- 宣言する束: <パッケージ名>`。その媒体に適用される決めの看板と違うと違反になる |
| 未反映の注記 | 提示物の先頭 | `- 未反映の注記: なし`、または `- 未反映の注記: <受託案件の見出し> — 覚え書き`。区切りより前が、その事実の入る先の節。指す節が無ければ違反、注記が残っていること自体は断りとして報告に出る |
| 出典の節 | `resume_ledger.md` の各案件 | `- 出典の節: <受託案件の見出し>`。受託案件の見出しに限り、公開可の節に限る |
| URL | `public_records.md` の各ブロック | `- URL: https://example.com/events/report/spring-meetup/`、または `- URL: なし`。提示物の本文に貼った URL は、同じホストのものだけがここと突き合わされる。経路の書き方だけが違うものも違反になる |
| 由来の節 | `public_records.md` の各ブロック | `- 由来の節: <職歴の枠か受託案件の見出し>`、または `- 由来の節: なし`。書いた見出しが実在しないと違反になる |

区切りの `—` は全角のダッシュ 1 文字である。日付は `2026-09-12` の形で書く。

## 書きの操作が書く形

決めの登記（`record_positioning`）とパッケージの改訂（`revise_package`）は、正本を下の形で書く。
手で書き足すときも同じ形にしておくと、読み戻しで落ちない。

**売り方の決め（`positioning.md`）。** 1 決め 1 ブロックで、末尾に積む。過去のブロックは書き換えない。

```
## 2026-09-16 全体

- 日付: 2026-09-16
- 適用範囲: 全体
- 前面に出す束: 要件定義と進行管理
- 根拠: 直近 3 件の引き合いが、作る前の整理に集中していたため。
- 例外: なし
```

見出しは「日付 適用範囲」の形にする。適用範囲は媒体の名前か「全体」で、媒体の名前は設定ファイルの
`channels` の綴りに限る。必須の欄は日付・適用範囲・前面に出す束・根拠の 4 つで、1 つでも欠けると
そのブロックは決めとして読まれず、検査の断りに「どのブロックのどの欄が無いか」が出る。
前面に出す束は `packages.md` にある節の名前に限る。例外は 1 行 1 件で、行を足せば何件でも書ける。
根拠のように文が長く複数行にしたい欄は、同じラベルの行を続けて書く（`- 根拠: 1 行目` の次の行に
また `- 根拠: 2 行目`）。読み戻すときは、同じラベルの行を改行でつないで 1 つの値に戻す。

**パッケージ定義（`packages.md`）。** 1 パッケージ 1 節。改訂は積まずに、その節を丸ごと差し替える。

```
## 要件定義と進行管理

- 最終更新: 2026-09-16
- 想定買い手: 専任の進行役を置けない、従業員 100 名前後の会社の事業責任者
- 仮説の状態: 検証中
- 判定根拠: 受注 2 件がどちらも継続している。
- 出典: engagements.md の「ナギサ書房 刊行計画の進行管理」
- 崩れる条件: 進行役を自社で採用できる規模の会社が、相手の中心になったとき
- 束ねる機能: 要件を決める場をつくる / 決まったことを段取りに落とす
```

節の見出しがパッケージの名前になる。最終更新は改訂の操作が今日の日付に進めるので、手で書く必要は無い
（手で書くときは、その束を前面に出した決めの日付以降にする）。仮説の状態は設定ファイルの
`package_hypothesis_states` の語に限る。束ねる機能は `capabilities.md` にある機能名に限り、`/` で区切る。
判定根拠・出典・崩れる条件は任意で、改訂の入力に無ければ前の節の値がそのまま残り、残したことが警告に出る。

**機能の台帳（`capabilities.md`）。** 機能の登記（`register_capability`）は、分類の節の表に 1 行足す。
その分類の節がまだ無ければ、節と表の見出しごと作って足す。

**公開記録（`public_records.md`）。** 公開記録の登記（`register_public_record`）は、1 件 1 ブロックで
末尾に積む。過去のブロックは書き換えない。

```
## 刊行計画の進め方を話した勉強会の発表

- 種類: 登壇
- 日付: 2025-11-08
- URL: https://example.com/events/report/spring-meetup/
- 発行元か主催: 出版まわりの仕事を持ち寄る勉強会（架空の催し）
- 役割: 登壇者
- 由来の節: ナギサ書房 刊行計画の進行管理
- 出所: 発表の資料と、主催が出した開催の記録
```

節の見出しが公開記録の名前になり、機能の裏づけの節はこの文字列で指す。必須の欄は名前・種類・日付・
発行元か主催・役割の 5 つで、種類と役割は設定ファイルの `public_record_kinds` と
`public_record_roles` の語に限る。日付は `2020-03-10` の形で書き、月までしか分からないときは
`2020-03`、年だけなら `2020` と書く。URL・由来の節・出所は任意で、値が無いときは「なし」と書く。

## 見せ方の正本の書き方

`presentation_rules.md` は、材料の取り出し（`assemble_material`）だけが読む。
accord はこの中身を型として持たない。見せ方の良し悪しは機械で判定しないので、読んで渡すところで止める。
ファイルの場所は設定ファイルの `[source.files]` の `presentation_rules` が指す。

| 節 | 何を書くか | どう返るか |
|---|---|---|
| `## <媒体の名前>` | その媒体の規約（文字数の上限、書き出しの決まり）と、その媒体での見せ方の決め | 宛先の媒体の節だけが「媒体の規約」として返る |
| `## 禁じた言い回し` | 媒体によらず使わない言い回しと、その理由 | どの媒体でも同じ一覧が返る |

節の見出しは、媒体の名前をそのまま書く（設定ファイルの `channels` と同じ綴り）。
中身は `- ` で始まる箇条書きで 1 件ずつ書き、箇条書きでない行は節に添えた説明として読み飛ばす。
宛先の媒体の節が無いときは、規約が空であることと、節を作れば返るようになることが警告に出る。
