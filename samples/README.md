# 同梱のサンプルについて

`source/` の中身は、すべて架空の人物と架空の案件である。実在の人物・会社・媒体とは関係が無い。
accord のテストと、初めて動かすときの確かめは、このサンプルの上で走る。

## 検査が読む欄の書き方

整合の検査（`check_consistency`）は、正本の次の欄を読む。欄の名前も区切りも、下の形で書く。

| 欄 | どのファイルのどこ | 書き方 |
|---|---|---|
| 最終更新 | `packages.md` の各節 | `- 最終更新: 2026-09-12`。この日が、その束を前面に出した決めの日付より古いと鮮度の違反になる |
| 例外 | `positioning.md` の各ブロック | `- 例外: なし`、または `- 例外: presentations/<媒体>/<ファイル名> — 理由`。1 行 1 件で、行を足せば何件でも書ける。ここに書いた提示物は、宣言と看板の一致の検査を飛ばす |
| 宣言する束 | 提示物の先頭 | `- 宣言する束: <パッケージ名>`。その媒体に適用される決めの看板と違うと違反になる |
| 未反映の注記 | 提示物の先頭 | `- 未反映の注記: なし`、または `- 未反映の注記: <受託案件の見出し> — 覚え書き`。区切りより前が、その事実の入る先の節。指す節が無ければ違反、注記が残っていること自体は断りとして報告に出る |
| 出典の節 | `resume_ledger.md` の各案件 | `- 出典の節: <受託案件の見出し>`。受託案件の見出しに限り、公開可の節に限る |

区切りの `—` は全角のダッシュ 1 文字である。日付は `2026-09-12` の形で書く。

## 書きの操作が書く形

決めの登記（`record_positioning`）とパッケージの改訂（`revise_package`）は、正本を下の形で書く。
手で書き足すときも同じ形にしておくと、読み戻しで落ちない。

**売り方の決め（`positioning.md`）。** 1 決め 1 ブロックで、末尾に積む。過去のブロックは書き換えない。

```
## 2026-09-16 全体

- 日付: 2026-09-16
- 適用範囲: 全体
- 前面に出す束: 要件定義と進行管理
- 根拠: 直近 3 件の引き合いが、作る前の整理に集中していたため。
- 例外: なし
```

見出しは「日付 適用範囲」の形にする。適用範囲は媒体の名前か「全体」で、媒体の名前は設定ファイルの
`channels` の綴りに限る。必須の欄は日付・適用範囲・前面に出す束・根拠の 4 つで、1 つでも欠けると
そのブロックは決めとして読まれず、検査の断りに「どのブロックのどの欄が無いか」が出る。
前面に出す束は `packages.md` にある節の名前に限る。例外は 1 行 1 件で、行を足せば何件でも書ける。
根拠のように文が長く複数行にしたい欄は、同じラベルの行を続けて書く（`- 根拠: 1 行目` の次の行に
また `- 根拠: 2 行目`）。読み戻すときは、同じラベルの行を改行でつないで 1 つの値に戻す。

**パッケージ定義（`packages.md`）。** 1 パッケージ 1 節。改訂は積まずに、その節を丸ごと差し替える。

```
## 要件定義と進行管理

- 最終更新: 2026-09-16
- 想定買い手: 専任の進行役を置けない、従業員 100 名前後の会社の事業責任者
- 仮説の状態: 検証中
- 判定根拠: 受注 2 件がどちらも継続している。
- 出典: engagements.md の「ナギサ書房 刊行計画の進行管理」
- 崩れる条件: 進行役を自社で採用できる規模の会社が、相手の中心になったとき
- 束ねる機能: 要件を決める場をつくる / 決まったことを段取りに落とす
```

節の見出しがパッケージの名前になる。最終更新は改訂の操作が今日の日付に進めるので、手で書く必要は無い
（手で書くときは、その束を前面に出した決めの日付以降にする）。仮説の状態は設定ファイルの
`package_hypothesis_states` の語に限る。束ねる機能は `capabilities.md` にある機能名に限り、`/` で区切る。
判定根拠・出典・崩れる条件は任意で、改訂の入力に無ければ前の節の値がそのまま残り、残したことが警告に出る。

**機能の台帳（`capabilities.md`）。** 機能の登記（`register_capability`）は、分類の節の表に 1 行足す。
その分類の節がまだ無ければ、節と表の見出しごと作って足す。

## 見せ方の正本の書き方

`presentation_rules.md` は、材料の取り出し（`assemble_material`）だけが読む。
accord はこの中身を型として持たない。見せ方の良し悪しは機械で判定しないので、読んで渡すところで止める。
ファイルの場所は設定ファイルの `[source.files]` の `presentation_rules` が指す。

| 節 | 何を書くか | どう返るか |
|---|---|---|
| `## <媒体の名前>` | その媒体の規約（文字数の上限、書き出しの決まり）と、その媒体での見せ方の決め | 宛先の媒体の節だけが「媒体の規約」として返る |
| `## 禁じた言い回し` | 媒体によらず使わない言い回しと、その理由 | どの媒体でも同じ一覧が返る |

節の見出しは、媒体の名前をそのまま書く（設定ファイルの `channels` と同じ綴り）。
中身は `- ` で始まる箇条書きで 1 件ずつ書き、箇条書きでない行は節に添えた説明として読み飛ばす。
宛先の媒体の節が無いときは、規約が空であることと、節を作れば返るようになることが警告に出る。
