# 同梱のサンプルについて

`source/` の中身は、すべて架空の人物と架空の案件である。実在の人物・会社・媒体とは関係が無い。
accord のテストと、初めて動かすときの確かめは、このサンプルの上で走る。

## 検査が読む欄の書き方

整合の検査（`check_consistency`）は、正本の次の欄を読む。欄の名前も区切りも、下の形で書く。

| 欄 | どのファイルのどこ | 書き方 |
|---|---|---|
| 最終更新 | `packages.md` の各節 | `- 最終更新: 2026-09-12`。この日が、その束を前面に出した決めの日付より古いと鮮度の違反になる |
| 例外 | `positioning.md` の各ブロック | `- 例外: なし`、または `- 例外: presentations/<媒体>/<ファイル名> — 理由`。1 行 1 件で、行を足せば何件でも書ける。ここに書いた提示物は、宣言と看板の一致の検査を飛ばす |
| 宣言する束 | 提示物の先頭 | `- 宣言する束: <パッケージ名>`。その媒体に適用される決めの看板と違うと違反になる |
| 未反映の注記 | 提示物の先頭 | `- 未反映の注記: なし`、または `- 未反映の注記: <受託案件の見出し> — 覚え書き`。区切りより前が、その事実の入る先の節。指す節が無ければ違反、注記が残っていること自体は断りとして報告に出る |
| 出典の節 | `resume_ledger.md` の各案件 | `- 出典の節: <受託案件の見出し>`。受託案件の見出しに限り、公開可の節に限る |

区切りの `—` は全角のダッシュ 1 文字である。日付は `2026-09-12` の形で書く。

## 見せ方の正本の書き方

`presentation_rules.md` は、材料の取り出し（`assemble_material`）だけが読む。
accord はこの中身を型として持たない。見せ方の良し悪しは機械で判定しないので、読んで渡すところで止める。
ファイルの場所は設定ファイルの `[source.files]` の `presentation_rules` が指す。

| 節 | 何を書くか | どう返るか |
|---|---|---|
| `## <媒体の名前>` | その媒体の規約（文字数の上限、書き出しの決まり）と、その媒体での見せ方の決め | 宛先の媒体の節だけが「媒体の規約」として返る |
| `## 禁じた言い回し` | 媒体によらず使わない言い回しと、その理由 | どの媒体でも同じ一覧が返る |

節の見出しは、媒体の名前をそのまま書く（設定ファイルの `channels` と同じ綴り）。
中身は `- ` で始まる箇条書きで 1 件ずつ書き、箇条書きでない行は節に添えた説明として読み飛ばす。
宛先の媒体の節が無いときは、規約が空であることと、節を作れば返るようになることが警告に出る。
